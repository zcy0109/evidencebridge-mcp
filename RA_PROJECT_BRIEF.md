# EvidenceBridge Multimodal MCP

## One-page project brief for research-assistant applications

EvidenceBridge is an auditable research workbench for legal, policy, teaching, and public-information materials. I built it to demonstrate full-stack AI application engineering through a difficult requirement that ordinary chatbots do not satisfy: every factual answer must expose its source, preserve the source location, pass a citation check, and cross an explicit human-review boundary when evidence is absent, conflicting, weak, or decision-critical.

The system is a TypeScript/Python monorepo. A Next.js and React interface provides document upload, a streaming conversation, live tool status, evidence cards, version-aware locators, and an audit view. Vercel AI SDK drives structured evidence selection and the response data stream, while server-enforced MCP preflight and post-selection verification prevent a credentialed model from bypassing citation or review gates. The default deterministic provider makes the complete demonstration repeatable without an API key. OpenAI-compatible and Azure OpenAI provider adapters share one interface. The Azure adapter is implemented but has not been verified against a live Azure deployment, so I do not claim hands-on Azure operation.

Agent capabilities are exposed through a TypeScript server built with the official Model Context Protocol SDK. Five tools are executable over stdio: document search, exact evidence retrieval, citation verification, document-version comparison, and human-review creation. A Flask/Gunicorn service validates and parses text, Markdown, and text-native PDFs; creates location-preserving chunks; performs transparent lexical ranking; verifies candidate quotations; records evidence; and produces stable audit events. Image and audio adapters preserve page/time metadata and accept explicit transcript fixtures, but do not pretend to provide OCR or speech recognition when no engine is installed.

PostgreSQL is the durable system of record. Prisma defines and migrates workspaces, documents, chunks, evidence, conversations, messages, tool calls, evaluation runs, human reviews, and audit events. The Next.js server uses Prisma for conversation persistence; Flask uses parameterised Psycopg access to the same checked-in schema. Docker Compose, seed data, Gunicorn settings, an Apache reverse-proxy example, and GitHub Actions complete the delivery path.

Evaluation is a first-class feature rather than a screenshot. The repository contains six synthetic source documents and 45 questions with gold answers, gold sources, answerability, and expected review labels. Saved deterministic runs compare direct answering, basic RAG, and RAG with citation-verification logic. Failure analysis identified wrong-version ties, short-title chunk bias, and a small set of transparent lexical mismatches. After implementing metadata-aware version filtering and content reranking, the same-set v2 regression reached 1.000 strict citation accuracy, retrieval recall, tool-call success, and review recall with a 0.000 unsupported/mismatch rate. The original v1 run is retained. These are in-sample component results after inspecting the same fixtures—not held-out or real-LLM results—and must not be presented as generalisation performance.

Security controls include file/type/page/size limits, filename normalisation, prompt-injection flagging, schema-validated tools, service authentication, timeouts, rate limiting, output escaping, privacy-conscious audit metadata, and server-controlled review decisions. The repository also includes a complete optional LoRA experiment for a three-way answer/refuse/review router; only its offline dataset and metric smoke test are claimed, not a completed training run.

This project connects my prior experience independently delivering database-backed enterprise backend modules with the target roles’ Python/Flask, TypeScript, MCP, Vercel AI SDK, PostgreSQL/Prisma, AI productisation, multimodal integration boundaries, testing, and reproducible research requirements.
